# Учётные данные DVC

Ключи S3-совместимого хранилища находились в отслеживаемых `.dvc/config` и
`.dvc_backup/config`. Они удалены из рабочих файлов, но остаются в старых коммитах
до отдельной очистки истории. Считать эти ключи скомпрометированными.

1. В Backblaze B2 отозвать опубликованный Application Key и проверить доступные
   журналы операций и состояние бакета. Само изменение Git-файлов ключ не отзывает.
2. При необходимости создать новый ключ с доступом только к нужному бакету.
3. Указать новые значения через `dvc remote modify --local b2remote access_key_id …`
   и `dvc remote modify --local b2remote secret_access_key …` либо через переменные
   окружения `AWS_ACCESS_KEY_ID` и `AWS_SECRET_ACCESS_KEY`. Не вставлять реальные
   значения в документацию, публичные логи или историю команд.
4. Проверить `git check-ignore .dvc/config.local`: файл должен быть исключён из Git.

## Очистка опубликованной истории

Переписывание истории меняет SHA коммитов и требует согласованной принудительной
публикации. Его нужно выполнять отдельно, после отзыва ключей и резервного копирования,
в отдельном mirror-клоне, сохранив текущие локальные изменения.

Если история именно этих двух конфигурационных файлов не нужна, `git-filter-repo`
позволяет удалить их из всех коммитов:

```bash
git filter-repo --path .dvc/config --path .dvc_backup/config --invert-paths
```

После фильтрации следует вернуть безопасный `.dvc/config` без ключей, проверить все
ветки и теги и согласовать публикацию переписанных ссылок. Другие клоны потребуется
переклонировать. Старые коммиты могут оставаться в кэшах, PR и чужих клонах;
при необходимости удаления таких ссылок нужно обратиться в поддержку GitHub.

Локальный перенос старых значений в игнорируемый `.dvc/config.local` сохраняет
настройки машины, но не делает старые ключи безопасными. После отзыва их нужно заменить
или убрать из локальной конфигурации.
